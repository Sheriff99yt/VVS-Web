## Implemented oracle

[The runner](../../packages/source-import/scripts/validate-csharp-native.ts) builds the trusted [Roslyn harness](../../packages/source-import/test/native-csharp/Program.cs), then parses, binds and emits the [fixture corpus](../../packages/source-import/test/native-csharp/cases.json) into memory. No emitted fixture assembly is loaded or executed. Source generators, user projects, build scripts and third-party analyzers are not part of this context.

Each probe records compiler acceptance/errors, syntax errors, expression type, contextual converted type, declared local type, nullable annotation/flow, exact constant kind/value, native operation kind, resolved invocation parameter types, conditional ownership and implicit property/operator/conversion/constructor effects. Contextual assignment conversion is recorded even when the source initializer itself is a literal. Warning IDs remain separate from blocking errors. String constants are represented by UTF-16 code units, avoiding lossy encoding of surrogate values.

The runner checks every expected field and required diagnostic, collects mismatches across the complete corpus and writes no successful evidence report when facts disagree. The [native evidence report](code_visual_csharp_native_evidence.json) is regenerated only after those checks pass. The combined runner has a dedicated csharp-native stage. CI configuration pins SDK 9.0.310 and checks the report; this chat has not observed a remote CI run or proved Linux portability of the assembly pins.

## Findings that change the implementation

| Native observation | Required graph/semantic contract |
|---|---|
| Byte arithmetic promotes to int; int/uint runtime arithmetic resolves to long in the tested case | Keep operand native identities and operator result typing separate from Number pin shape. Do not copy Go's same-native-type arithmetic policy. |
| A constant int initializer can contextually convert to byte | Assignment compatibility depends on the expression's constant evidence and the visible declaration type. It is not an implicit emitted cast. |
| A constant fractional double-to-int cast truncates; unchecked byte casts wrap | Implement C# conversion and checked-context rules independently of Go's constant representability rules. Preserve the authored cast/checked construct and original operand token. |
| Float and double constant casts round beyond their exact integer domains; decimal remains a distinct domain | Exact transient arithmetic may be reusable, but native rounding/promotion/decimal policy needs its own contract. Stored JS Number values cannot own large integral literals. |
| Native strings/chars retain UTF-16 units, including a surrogate char/string in the tested cases | Preserve native character/string/token identity. Go byte strings and Go's surrogate rejection policy cannot be reused. |
| A var string local can have declared type string? while its initializer has type string and NotNull flow | Store/check declared type, expression type, converted type and flow separately. Nullable flow is not a new persisted source annotation. |
| A nullable dereference can compile with warning CS8602 | Retain native diagnostics and native warning/error severity; do not classify all compiler diagnostics as invalid syntax. |
| Overloads resolve after argument promotion and across explicit reference context | Resolve exact callable/parameter identities from the native contract; do not bind calls only by name or graph pin category. |
| Conditional invocation, ternary and coalescing operands have distinct guard paths | Reuse visible expression ownership after its C# policy is verified; include native conditional syntax rather than eager call placement. |
| A guarded property getter invokes behavior without InvocationExpression syntax | A no-call syntax walk cannot establish purity. Model accessors and operator/conversion effects from binding as well as explicit calls. |
| A literal assigned to Counter resolves a user-defined implicit conversion | Contextual conversion can invoke user code. Keep the visible declaration/type and resolved conversion contract; do not treat literal evidence as proof of a pure assigned value. |
| A multi-file alias resolves a constant in another namespace; missing external bindings fail | Establish compilation-unit paths, namespace/type/alias identity and reference closure before project acceptance. |
| C# 12 collection expressions require target typing in the tested array declaration | Contextual expressions need explicit destination ownership; parser recognition alone cannot select their type. |

These are bounded native observations, not exhaustive language laws proved by this corpus. The [C# expression specification](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/expressions) and [numeric conversion reference](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/numeric-conversions) guide the broader policy research. Roslyn's [IOperation API](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.ioperation?view=roslyn-dotnet-4.14.0) supplies bound operation evidence. Current documentation does not expand the pinned C# 12 acceptance profile.
