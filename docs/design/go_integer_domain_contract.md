# Go integer domain contract

The shared integer contract in `packages/graph-types/src/goIntegerSemantics.ts` is an implementation prerequisite for the open MP-09 integer-import item. The Go adapter now accepts exact integer token payloads, native integer operators, fixed-width and word-sized bindings through IR v9. Visible signature/local settings, the package word-size choice and shared graph constant/type checks survive editing, source emission, save/reload and re-import. Full Go numeric coverage still requires the remaining contracts below.

The contract covers signed and unsigned fixed widths, `int`, `uint`, `uintptr`, and `byte`/`rune` identity aliases. Word-sized types require an explicit 32/64-bit context. Integer literals retain exact magnitude through decimal/binary/octal/hex tokens and underscores; unary signs are separate operations. Semantic facts use canonical decimal strings. BigInt values and descriptors are transient analysis data and never become saved graph values.

Assignment checks native type identity and representability. Typed widths are not interchangeable through a generic Number pin, and no implicit conversion is introduced. Exact constant arithmetic implements truncating division/remainder, bit operations, shifts, typed overflow and division-by-zero checks. Dynamic values retain their native type without fabricated constant values; runtime arithmetic stays in the generated Go operation. Short declaration inference selects native `int` using the explicit target word size.

The pinned fixture profile limits constant result precision to 512 bits and constant-expression shift counts to 1074. Zero left shifts and sign-preserving right shifts retain their exact bounded result. Nonconstant shifts keep native runtime behavior and independently typed counts; untyped constant counts must represent uint under the target context. No runtime shift is evaluated. The big.Float fallback, float32 graph binding and complex constants, defined numeric types, casts, iota and build-context selection remain separate required contracts. This module must not be presented as complete Go numeric coverage.

The independent fixture validator uses Go 1.26.4 `go/parser`/`go/types`, explicit `gc` sizes for `386` and `amd64`, and native constant/type observations. The 251 handwritten probes compare every width boundary, aliases, inferred word-size overflow, exact large/radix literals, signed division/remainder, complement, mixed-width failures, typed constant overflow, dynamic arithmetic and shifts. The checker parses and checks trusted fixtures; a compile-only stage also validates the curated source/generated fixture pairs. Neither executes imported programs. These probes are a separate denominator from the 78 ordinary Go visual units plus four explicit word-context units.

Reference: [Go numeric types](https://go.dev/ref/spec#Numeric_types), [constant expressions](https://go.dev/ref/spec#Constant_expressions) and [representability](https://go.dev/ref/spec#Representability). The published specification can describe a newer version; acceptance stays pinned to the tested Go 1.26 profile.

The integration stage must preserve exact literal tokens as validated scalar payloads, explicit integer types on signatures/locals/operators, and visible architecture context. Width/sign/constant checks must also run against edited/saved graphs, not just the initial parser plan. Increasing-complexity fixtures must combine default integer loop indices, typed unsigned arithmetic, same-file calls and branches, plus out-of-range constants and incompatible edited widths. Re-import must retain the target context and block stale receipts after it changes.

Fixed-width integration uses native type identity on each declaration, call argument/result, assignment, arithmetic/comparison operand and return. Binding refresh preserves compatible authored types. JSON reload and Code-panel tests cover every mapped node; mutation checks reject width/sign changes and numeric inline values lacking an exact integer payload. Independent Go AST/type pairs verify all eight fixed widths and aliases, including runtime integer division and loop updates. The production browser corpus adds signed division and unsigned same-file pipeline import/accept/reload checks.

Exact literal integration stores original lexer-validated tokens, never JS Numbers or BigInts. Native operators retain their source operands/operator on visible nodes; transient exact values exist only for semantic evidence. Default short integer declarations infer int under the package node's 32/64-bit choice. The import dialog and Package Clause inspector expose this setting, and worker acceptance checks it against the reviewed graph. Re-import constructs baseline/incoming graphs under the current explicit word context and seals the complete current snapshot; changing context after review invalidates acceptance. Native Go fixtures use gc/386 or gc/amd64 sizes matching that choice. Dynamic unsigned/signed overflow stays in native Go operations. Context-dependent shifts resolve destination types through declarations, assignments, returns, calls, comparisons and typed peers. Simple nested nonconstant counts remain untyped and are checked against the pinned compiler literal-storage domain without inventing runtime values or types. Composed untyped counts and the big.Float fallback remain open feedback cases. Exact rational arithmetic and float64 assignment rounding are integrated below. Four independent observations preserve the go/types/compiler divergence for out-of-storage nested count literals at both architectures.

Full Go numeric compound assignments use explicit operator settings in IR v9. Non-shift updates require assignment-compatible native operands; shift updates check their independently typed count. Code-panel validation repeats these rules after visible edits and JSON reload.

## Exact floating constant integration

`goRationalSemantics.ts` supplies transient reduced fractions for Go decimal and hexadecimal float tokens, exact untyped arithmetic, integer representability and native floating assignment rounding. `goValueSemantics.ts` shares this evidence between source import and edited graphs. Tokens remain original strings in the `go-float` domain; mixed numeric operations use `go-number`. Print preserves their native source spelling. Float64 typed operands round before further typed arithmetic; zero division checks use the resulting native constant, including a denominator that underflows to zero. Integral floating constants used as shifts obey Go's destination/default inference rules. Numeric pins alone cannot prove a floating type.

The independent 75-observation corpus covers valid/invalid literal grammar, fractional/integral constants, float32/float64 exact rounding, ties-even boundaries, subnormals, underflow, overflow and typed/untyped arithmetic. Float32 observations prove the kernel only: graph signatures and local binding integration still require work. Fraction components must stay below 4096 bits, matching the Go constant library's rational arithmetic domain. Go uses a distinct 512-bit big.Float fallback outside that domain; importer prerequisite diagnostics are not claims of language invalidity. The native-valid ratio `1e1400 / 1e1400` records this gap.

## Float32 binding and explicit numeric conversions

Float32 now participates in visible signatures, declarations, calls, arithmetic, comparisons and updates; no widening is inferred from Number pin shape. Native assignment identity distinguishes float32 and float64. `goValueConvert` preserves explicitly authored runtime conversions with target-type facts only and checks constant conversions against exact native representability. The Go-only `conversion` NativeExpression form has one operand and a visible nativeTargetType enum. Its syntax pack emits `target(value)`. Constant conversion preserves already-rounded source-type evidence before destination rounding; aliases byte/rune preserve native integer identity. Cast targets cannot be shadowed by a parameter or same-file function in edited graphs. Numeric casts do not implement string/rune decoding or named/defined type conversion.

Independent conformance adds 271 conversion observations at both word sizes, including constant failures, all numeric source domains converted at runtime, word-dependent representability and nested float32-to-float64 rounding. The kernel and graph binding share these checks; no imported program is executed.
