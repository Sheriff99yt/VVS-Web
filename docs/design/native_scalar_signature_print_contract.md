# Native scalar header print contracts

Rust/C++/GDScript syntax packs now own ordinary scalar parameter and function-open templates. Pure transpiler printers validate authored/canonical native signatures and explicit modifiers before rendering. Parameter qualifiers retain C++ const and Rust mut; authored C++ aliases and Rust integer widths remain exact. Rust omitted versus explicit unit return is an explicit option. No receiver, visibility, async wrapper, conversion or declaration is inferred. Header spans belong to the visible Function Define.

The shared function-header renderer consumes these printers for the reviewed native signature context, rejecting async/constructor/destructor and C++/Rust non-module contexts. The existing public native-signature admission guard still excludes these three targets. This provides emit syntax infrastructure without enabling an unverified graph/import adapter. Registry/inspector settings, full native body/project ownership and canonical new-adapter Code-panel/browser acceptance remain required.

`native-signature-print` rebuilds supported headers from the independently checked source signature corpus, then combines them with trusted fixture bodies and type-pointer probes solely for native validation. Production code never consumes saved original source to emit bodies. All generated compiler inputs are hashed and checked under the existing pinned compile-only profiles; unsupported header cases are excluded. This is header print evidence, not saved-graph function emission or adapter certification.

Batch gates: packages, source-import types, native host types, native-signature-print, disk-loaded goldens and canonical Code-panel output. Existing-adapter/native/browser assets are unchanged, so their compatible evidence is retained; the new generated header inputs receive fresh compiler checks. The explicit print stage is excluded from defaults pending tool provisioning and skips after fresh package/type failure. Changed pack behavior receives the required existing Code-panel/golden regression checks once.
