# Shared native integer/Boolean constant operators and conversions

`evaluateNativeConstant` evaluates immutable literal/unary/binary/explicit-conversion trees under the pinned Rust/C++/GDScript profiles. Results retain exact decimal-string integers or Boolean values, native types/width/signedness and literal warnings. This is the `integer-boolean-constant-expressions` domain: no calls, variable effects, dynamic overflow policy, source/graph ownership or graph receipt. Graph admission remains blocked. Cycle/depth/node budgets bound supplied trees.

| Profile | Implemented constant rules | Native boundary |
|---|---|---|
| Clang19.1.5 C++17 Windows MSVC LLP64 | Integral promotions including bool/narrow casts; usual arithmetic conversions and signed/unsigned rank; exact arithmetic/comparisons/bitwise; unsigned wrapping, truncating division/remainder; bounded shifts; explicit Boolean and fixed-width integer conversions | Independent static_assert types/values and constexpr rejection; signed narrowing/right-shift behavior is pinned implementation behavior. Sign-changing signed left shifts remain unsupported pending their native contract |
| rustc1.99 edition2021 Windows MSVC pointer64 | Same-type integer operations, eager bool bitwise/equality, const overflow rejection, truncating division/remainder, independently typed bounded shift counts with truncation, explicit as narrowing/bool-to-integer, directly/grouped negated signed-minimum literal exception | Const value/type assertions and rejected type/overflow/cast/shift cases; constant rejection does not define release-mode dynamic overflow behavior |
| Godot4.5.2 | int64 arithmetic/wrapping, comparisons/bitwise, truncating division/remainder, bounded shifts, explicit int/bool conversions, exact directly versus grouped negative literal behavior | Isolated check-only constant type/value assertions; negative bit-shift operands are rejected by the native engine. Broader shift-count, division-limit and dynamic behavior remain required |

References: [Rust operators/casts/overflow](https://doc.rust-lang.org/reference/expressions/operator-expr.html), [C++ usual arithmetic conversions](https://eel.is/c++draft/expr.arith.conv), [GDScript operators](https://docs.godotengine.org/en/4.5/tutorials/scripting/gdscript/gdscript_basics.html). Profile-specific assertions govern each supported boundary; similar syntax does not transfer semantics.

## Independent packet and consolidated acceptance

`tools/native_constant_cases.json` contains independently authored expression spellings/trees and expected native types/values, including composed arithmetic, mixed signed/unsigned ranks, bool promotion, narrowing, negative division/remainder, overflow, shift truncation and directly/grouped minima. The pinned assertion harness is shared with the scalar packet, but each source is compiled independently of VVS evaluation. Exact actual UTF-8/LF input hashes and three false-assertion calibrations are mandatory. No programs execute.

October7 verified evidence:116 native cases (113 comparisons/3 false assertions),3,672 package tests and public API types pass. The shared harness change also passed the existing89 native literal cases. First native execution exposed Windows-incompatible comparison IDs; stable word IDs repaired filenames. Native Godot negative-shift rejection then corrected an assumed arithmetic shift, while grouped Rust minimum review repaired its special literal context and unsigned-negation diagnostic. Final retry compiled one failed Godot case and retained115 matching native cases; all toolchain pins, unchanged source hashes/expectations and retained failures are checked. Package/type gates were retried only after these affected repairs; unchanged application/native-initialization/binding/Pages/browser evidence is retained.

Normal gate: `bun tools/validate_batch.ts --only=packages,source-import-types,native-constants`. A saved failure can be repaired with `--retry-native-constants=<language>/<case-id>`; missing/stale changed inputs or toolchain pins fail retained evidence. Other failures remain failures until their affected cases are selected. The consumer checks the complete report after the retry. This portable native stage is explicit and excluded from default validation pending provisioning.
