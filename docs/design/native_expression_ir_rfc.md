# MP-02b native expressions: IR v4 amendment

## IR v18: predefined C# Boolean values

NativeExpression settings now admit `csharp-bool` results for authored Boolean tokens, integral comparisons, Boolean logical/bitwise/equality operators, negation and explicit parentheses/overflow wrappers. Result pins are Boolean; numeric consumers continue using the strict integral inference wrapper. Ordered operands and per-node spans remain intact even when short-circuit facts show an unreachable operand. Static methods may return bool with their existing integral parameters/locals; Boolean bindings/parameters, branch statements and full wider value domains remain separate required work. No persisted constant cache or implicit numeric truth conversion is introduced.

The authorized MP-02b implementation adds structured native scalar, collection, entry/spread/hole, access and operator expressions. IR v4 extends the expression union with `NativeExpression`: a reviewed form, exact scalar payload or identifier/operator setting, ordered child expressions and an owning canvas node ID. It contains no editable source snippets or parser trees. Existing v3 expression variants remain unchanged; IR is regenerated from saved graph v3 snapshots, so no persisted IR migration is required. Existing graph kinds keep their meanings and versions.

Four registry families expose literal values, collection/entry forms, native access and native operators. Collection arity creates visible ordered input pins. Object/dict entries are individual visible nodes; computed keys, spread and array holes are explicit forms. Scalar payloads use tagged validated numeric text (preserving negative zero/overflow), decimal integers or decoded string values; inventory evidence retains the original binary64 bits. JavaScript null and Python None remain distinct. Native operator modes delegate coercion/overload/error behavior to the source language's actual operator, never to numeric Math or an injected conversion. Cross-language targets without a reviewed mapping block analysis and printing.

All operands remain graph wires/inline literals. Calls used as values retain their explicit execution ownership and print at their original expression positions; they are not duplicated as statements. The printer preserves native operand/key order, access errors, spread semantics and holes. Unsupported bindings, short-circuit/cleanup constructs and other profiles retain blocking diagnostics. Original source provenance is immutable evidence, not an authoring field.

Analyzer gates validate forms, target/domain, exact payloads, operand count/pins and required inputs. Lowering repeats these gates before constructing IR. Every expression and syntactic hole owns generated spans. Pack rows own simple syntax; native printers handle scalar decoding and variable-length assembly. Evidence includes native AST comparisons, JSON save/load, Code-panel output, graph mutations, effectful mixed examples and browser acceptance/re-import/reload. MP-02a recognition alone remains insufficient for acceptance; probe status changes require this evidence.
