# C# authored declaration groups

The visible `csharp_declaration_group` node owns a shared predefined integral type and typed/const style. Its Declarators execution output owns two to thirty-two visible Variable Define children in source order; its continuation output connects the following statement. Children retain their own stable symbol IDs, initializers and name spans. Group ownership is independent of lexical scope ownership: grouped locals live in the surrounding block rather than a new declaration space.

IR v16 `DeclarationGroup` prints one authored comma-separated statement through the C# pack. Each declarator receives its exact name/initializer source range, while expressions keep nested ranges and the owner maps the whole statement. The native graph walk pre-reserves group names in the enclosing space, evaluates and introduces initializers in order, and rejects malformed membership, shared-type/style drift, forward reads, cycles, duplicate/shadowed names and escaped scope references. Generation derives these facts from graph nodes without source provenance.

Group and child inspectors edit the shared type/style through one pure projection and one lifecycle transaction, including each declaration's native metadata and readonly variable index. `var` groups are invalid in C# and unavailable in grouped style choices. Invalid native conversions or const initializers still block generation; the same shared edit restores a valid state. Individual symbol renames preserve group identity.

Composed source/native fixtures cover ordered mutation, const dependencies in unchecked scopes, sibling group identities, exact signed minimum tokens and void completion. The fixed saved graph covers exact comma syntax, precise source ranges, reload, provenance-free generation, native invalid/recovery and malformed ownership/order/count/type. Production and Pages browser proof uses two groups together and checks actual type/style edits, readonly indexes and save/reload.

IR17 now preserves absent initializers in typed mutable groups, with separate declaration/initialization facts and assignment propagation through lexical blocks; see [the definite-assignment contract](csharp_definite_assignment_contract.md). Const groups still require every initializer. Conditional merges, loop fixed points, exception/ref-out paths, group membership editing, split/merge transactions and detailed declarator trivia require further contracts. They remain part of the full reverse-import objective; these integral groups do not certify full C# declaration support.
