# Native adapter compilation units

The approved all-language reverse-import goal includes Verse/UE6; its grammar and independent validator remain prerequisites, not reasons to claim completion.

IR v5 adds `PackageDecl` as an ordered member with a visible source node. The first use is the Go package clause. It is never inferred from metadata or inserted as a hidden preamble. Native file-function signature records can additionally declare reviewed parameter and return types. Go's initial reviewed types are `float64`, `string` and `bool`, with exact pin correspondence. This is an adapter stage, not complete Go coverage; integer domains, grouped/variadic parameters, multiple results, methods, interfaces, packages/imports, defer and concurrency require further contracts.

The browser parser loads pinned local WebAssembly grammar/runtime assets, supports cancellation and size/depth/time limits, and produces transient CST data only. Accepted graphs contain typed visible constructs, never opaque CSTs or editable source snippets. Unsupported source remains intact in review. Same-language source structure, normal Code-panel output, save/load and conflict-aware reimport must be checked. Independent Go parser/type-checker fixtures never execute imported source.

Existing graph snapshots regenerate the additive IR. Legacy emit changes needed for valid typed Go signatures are verified against existing graph fixtures; new adapter claims require their own native and browser evidence.

## IR v6: Go local declarations and native loop headers

Scoped Declare nodes retain `nativeLocalStyle` (`go-short` for `:=`, `go-var` for an explicit typed `var`) and the reviewed scalar `nativeType`. These become structured DeclareLocal fields, not source snippets. Short numeric initializers require proven float64 values; integer-default inference is a separate domain contract. Explicit typed declarations retain their initializer without inserting conversions. Local identity, block scope, shadowing, use and dominance must remain visible and checked.

Existing structured For and While nodes represent Go counted and condition-only loops. Initializer/condition/update stay separate visible graph nodes; Go has postfix statement updates only. Nearest-loop Break/Continue retain their explicit ownership. Native syntax packs print declarations, assignments and headers; composed fixtures independently type-check and compare ASTs. Multi-name declarations/redeclarations, grouped declarations, named results, range iteration and integer widths remain separate contracts.

## IR v7: fixed-width Go integer bindings

Native signature and DeclareLocal type fields include fixed-width signed/unsigned integers and byte/rune aliases. Numeric pins remain the common visual category; their native type identity is checked independently at every declaration, call, operator, assignment and return. Binding refresh preserves a compatible authored native type instead of replacing it with float64. This stage accepts dynamic typed values, not untyped integer literal payloads, word-size-dependent types, casts or opaque source. Integer arithmetic prints native Go operators with no evaluation or conversion. Literal representability and architecture settings remain required follow-up work.

## IR v8: exact Go integer tokens and target word context

NativeExpression accepts Go scalar integer tokens and explicit unary/binary integer operators. Token payloads are lexer-validated strings with exact constant evidence; JS Number/BigInt values are not saved as integer literals. Runtime operators remain visible operators and are emitted without folding or conversions. Native integer assignment, inference, comparison, calls and returns use the shared exact contract. PackageDecl retains the visible package node's 32/64-bit word-size context, which is chosen in import review and editable on the package node. Word-sized types and default integer inference require this context; it is retained during source replacement and included in stale-receipt checks. Old float-only saved graphs need no invented architecture record. Rational/float/complex constants, defined types/casts, iota, contextual nonconstant untyped shifts and wider project/build-context closure remain separate required contracts.

## Integer context and compound-operation conformance

Go untyped nonconstant shifts retain transient deferred type evidence until an assignment, return, parameter, typed peer or default-inference context resolves their native type. Deferred evidence is never saved or emitted as a conversion. Unary/composed operations and shift-count contexts must follow Go typing rules, including representability before a variable shift. Native constant shifts follow the pinned go/types 1074-count/512-bit limits; dynamic shifts keep their native operation and no fabricated constant result. AssignVariable supports Go remainder, bitwise and shift compound operators in IR v9. Shift counts retain independent integer types; non-shift compound values must satisfy the local's native identity and representability.

## Exact Go floating constants

Native scalar settings accept a Go float token domain with lexer-validated decimal/exponent/hex-float spellings. Original tokens remain visible payload strings and emission preserves them. Native unary/binary operators retain numeric operands explicitly; transient exact fractions determine untyped float identity, integrality, representability, destination rounding and zero division. Typed runtime expressions retain their authored native types without evaluation. Rational evidence stays within the pinned Go constant library fraction domain; its wider big.Float fallback remains a separate prerequisite, not a language-invalidity claim. No fractions, rounded values or conversions are persisted or emitted.

## IR v10: native float32 binding and explicit numeric conversion

Native scalar signatures/local fields add float32, preserving native identity independently of numeric pins. Structured NativeExpression settings add the Go-only conversion form with one operand and a validated visible nativeTargetType. The native syntax pack emits target(value) from that setting, with source mapping for the conversion and its operand. Runtime conversions are preserved without evaluation; constant conversions check representability/rounding from the existing exact facts. No conversion is inserted for assignment or emission. Generic casts, defined types, string/rune conversion and unsafe/pointer conversions remain separate contracts.

## IR v11: visible Go constant declarations

DeclareLocal adds go-const style and a visible untyped native type choice for constants only. The declaration owns its initializer, readonly binding and optional explicit scalar type. Shared transient facts preserve exact referenced constants and declaration-time rounding; saved graphs retain expressions and names, never evaluated values. Go boolean/string operators and constant comparison facts preserve ordinary source operators and source maps. Local constants may be unused; variables retain Go's use requirement. Assignments, cycles, dynamic initializers and inconsistent readonly/type/pin records block generation. Package constant members, declaration groups/iota and defined types require the corresponding file/scope contracts; this amendment does not manufacture those constructs from symbol indexes.

## Conditional expression ownership preflight (October 5, 2026)

The shared transient expressionCallSites analysis identifies each call occurrence by its operand path, preserves argument-before-call dependency order and attaches enclosing conditional right-operand owners. It handles every current ExpressionPlan variant with bounded traversal. Go logical operators, JS logical/nullish operators and Python logical operators have distinct guard policies; representing them in preflight does not enable new grammar mappings. The analysis does not declare non-call expressions pure or evaluate source.

Materialization rejects conditional call sites before inserting an eager call chain. The Go parser uses the same recursive call inventory rather than a private incomplete walker. This preserves the existing blocking Go short-circuit gap and prevents a typed plan from bypassing it. Existing lowering already has IrCallExpr and omits a standalone call statement when the return is consumed; the next graph contract should reuse that native expression emission. The eager graph execution queue is insufficient proof of conditional ownership even when generated syntax happens to preserve it. Existing eager left-only calls remain supported. Full acceptance requires a subsequent visible graph/IR construct that owns effectful expression regions and emits the authored expression exactly once; it must distinguish ordered argument effects, conditional operands, repeated loop conditions, cleanup and suspension. No IR version bump or new persisted semantics is introduced by this preflight implementation.

Required graph design: a call occurrence has exactly one evaluation owner, either a statement/ordered execution region or an enclosing expression region. Conditional right operands inherit their native expression owner, never an unconditional statement predecessor. Reused results versus repeated occurrences must be explicit; connecting an effectful value to two consumers cannot silently duplicate or cache the call. Source maps must cover the visible call and region. Source/edited-graph validation, native AST/type/compiler evidence and actual Code-panel/browser mutation/reload checks are required before enabling conditional-call acceptance.

## Visible Go expression-call ownership (October 5, 2026)

Call Function gains visible callPlacement (statement/expression). Expression calls have only value argument/result pins. Their single outgoing value edge and subsequent single-consumer expression path identify their owning reachable statement or loop header. They never enter an eager execution chain. Binding/overload refresh preserves placement and removes/restores execution pins; the inspector exposes this setting for Go and cleans invalid execution edges when switching to expression mode.

Graph validation blocks missing/invalid owners, cycles, orphan expressions, execution pins/edges on expression calls, call or intermediate-expression fan-out, unknown placement, eager call dependencies and use outside the reviewed Go profile. Scope validation follows argument dependencies through the owning statement. Existing IrCallExpr preserves native ordered/conditional expression syntax and source maps; no new IR type or hidden temporaries are introduced. Go imports now give every value call expression ownership; statement calls retain execution placement. Loop condition calls stay in their native repeated header expression.

Eight composed source/generated units, a fixed saved graph with nested conditional calls, mutation/binding-refresh tests and four browser workflows exercise this contract. Native/compiler/Code-panel/browser validation passes all 18 stages; saved-graph mutation and both conflict-aware worker reimport choices also pass. This integrates conditional Go calls; JS/Python policy integration, exceptions/cleanup/suspension and advanced/project/language scope remain required.
