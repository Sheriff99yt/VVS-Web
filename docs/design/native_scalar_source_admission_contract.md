# Native scalar source admission and lifecycle

The C++17 Windows/MSVC LLP64, Rust edition2021/rustc1.99 Windows/MSVC library and Godot4.5.2 profiles admit whole ordinary scalar Library modules. The subset comprises explicit native function signatures, resolved parameter identity returns, exact integer/Boolean constants/operators/grouping/conversions and unit returns. Rust final-value returns retain authored tail spelling. This does not admit runtime parameter operations, locals, general control/effects, wider types/projects or special entry/constructor roles.

Source preview retains the entire source/hash/inventory and returns no worker receipt or accepted project. Worker review rebuilds a complete graph, resolves registry kind versions, validates ownership and native structure, compares canonical generated syntax and checks serialization. Acceptance requires the private review seal and current worker generation. Source/filename/language/policy/snapshot mutation, copied reviews and replayed worker receipts reject. Original source is provenance, never generated-code authority.

Target-specific flat source filenames are validated before graph analysis and direct emission. Explicit paths cannot escape the module or collide under case folding. Accepted projects preserve current-v3 metadata, stable function identities, definition-owned bodies, source origins and library policy. Rust unsuffixed literal types derive from visible return/cast/peer contexts; source-analysis hints cannot freeze later edits.
